## Findings

### [high][security][config] CalDAV account passwords stored in plain text on disk
Evidence: `crates/mgmt-config/src/lib.rs:318`
Account struct password field is `Option<String>`, serialized plaintext to `caldav.yaml`. No encryption at rest; 0600 perms only, plaintext persists across backups/syncs.
Repro: add CalDAV account with password via web UI; read `~/.config/mgmt/caldav.yaml` — plaintext.
Suggested test: blackbox — read caldav.yaml after adding account, verify password not plaintext (currently fails).

### [high][bug][sync] Base snapshot silent failure on file I/O errors risks data loss
Evidence: `crates/mgmt-sync/src/http.rs:143`
`BaseSnapshot::load` uses `.unwrap_or_default()` on read/parse failure — silently discards I/O/corruption errors, continues with empty base. Corrupted/missing/permission-denied snapshot causes lost conflict-resolution history, spurious conflicts, repeated pushes/pulls.
Repro: sync a vault, corrupt `.state/sync/<pairing>/<coll>.json` (chmod 000), run sync.
Suggested test: unit + blackbox — corrupted base file should error, not silently lose history.
